## FighterFish

OSGi Application Development using GlassFish Server.

## Build

You must build using JDK 21 or newer. You also need Maven 3.9 or newer.

The modules target GlassFish 8.0.4 (Jakarta EE 11, Apache Felix 7, OSGi Core
 R8). The integration tests download GlassFish 8.0.4 and run it embedded in
 Felix with Pax Exam.

**Full build**
```bash
$ mvn clean install
```

A clean build is recommended: the bundle manifests are generated by bnd and are
 not always regenerated by an incremental build.

**Integration tests only** (after a full build)
```bash
$ mvn verify -pl test/util,test/it
```

**Checkstyle**
```bash
$ mvn validate  -Pcheckstyle
```

**Copyright**

```bash
$ mvn validate  -Pcopyright
```

**Spotbugs**

```bash
$ mvn verify  -Pspotbugs
```

## Deployment on GlassFish 8.0.4

Copy the jars of the `module` directory to `glassfish/modules/autostart`.
 Besides the bundles shipped with GlassFish, some features need additional
 bundles in the OSGi framework:

| Feature | Required bundles |
|---------|------------------|
| OSGi HTTP Whiteboard (`org.osgi.service.servlet`) | none |
| OSGi `HttpService` compatibility (`org.osgi.service.http`, `javax.servlet` API) | `javax.servlet-api` 4.0.1, `org.apache.felix.http.wrappers` 6.1.0 |
| Declarative Services in application bundles | `org.apache.felix.scr` 2.2.x, `org.osgi.util.promise`, `org.osgi.util.function` |

`osgi-http` implements the OSGi Servlet Whiteboard 2.0 specification on the
 GlassFish web container and registers an `HttpService` adapter on top of it
 when the compatibility bundles above are installed.

Web application bundles (WAB) that embed jars with `Bundle-ClassPath` must
 import the packages used by the embedded classes explicitly: bnd only analyzes
 the classes of the bundle itself, and annotations whose classes are not
 visible to the bundle (such as `jakarta.inject.Named`) are silently ignored.
